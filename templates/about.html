⚖️ 1. Cryptography vs. Steganography

A fundamental concept in information security is understanding the complementary relationship between cryptography and steganography:

Security Dimension Cryptography (Encryption) Steganography (Data Hiding)
Primary Objective Hides the meaning (content) of a message. Hides the existence of the communication.
Visibility to Eavesdropper Ciphertext is overtly scrambled and visibly suspicious. Carrier image appears completely benign and natural.
Failure Scenario Attacker knows data exists and may attempt cryptanalysis. If detected, the raw hidden data is exposed (unless pre-encrypted).
Defense-in-Depth Solution Our Combined Pipeline: The message is first encrypted with AES-256-GCM, then embedded into the image using LSB steganography. Even if an adversary intercepts or detects the stego image, they cannot decrypt the payload without the passphrase.

🔐 2. Cryptographic Engine (AES-256-GCM + PBKDF2)

Our cryptographic layer adheres to modern high-assurance standards:

  • PBKDF2-HMAC-SHA256: Converts the user's password into a 256-bit AES key using 600,000 iterations and a unique, cryptographically random 32-byte salt generated via os.urandom(32). This design actively resists GPU-accelerated dictionary attacks.
  • AES-256-GCM (Galois/Counter Mode): Authenticated symmetric block cipher operating with a fresh 12-byte (96-bit) nonce per hide operation. It produces ciphertext and a 16-byte (128-bit) authentication tag to guarantee both confidentiality and authenticity.

#️⃣ 3. SHA-256 Integrity Verification

To provide an educational demonstration of hashing as a separate CNS concept:

$$\text{Digest} = \text{SHA-256}(\text{salt} \parallel \text{nonce} \parallel \text{ciphertext})$$

The 256-bit digest is stored in the versioned payload. During extraction, the receiver recalculates this hash before decryption. A mismatch indicates pixel alteration, carrier corruption, or payload tampering. Verification is performed using hmac.compare_digest() to mitigate timing side-channel leaks.

🖼️ 4. Spatial-Domain LSB Steganography

In 24-bit RGB images, each pixel consists of three 8-bit color channels (Red, Green, Blue) ranging from 0 to 255. The least significant bit (LSB, bit position 0) holds the smallest mathematical value ($2^0 = 1$). Modifying this bit changes the channel luminance by at most 1 unit — imperceptible to the human eye.

Bit Modification Formula: 

new_channel_value = (original_channel_value & 0xFE) | payload_bit

Capacity Formula: $$\text{Capacity (bytes)} = \left\lfloor \frac{\text{Width} \times \text{Height} \times 3}{8} \right\rfloor - 4 \text{ (header bytes)}$$

📈 5. Image Fidelity Metrics (MSE & PSNR)

To quantify the imperceptibility of the steganographic alteration, we calculate two standard metrics:

  • Mean Squared Error (MSE): Average squared difference between original and stego channel values. $$\text{MSE} = \frac{1}{W \times H \times 3} \sum_{x,y,c} \left(I_{\text{orig}}(x,y,c) - I_{\text{stego}}(x,y,c)\right)^2$$ Lower values denote higher fidelity (0.0 represents identical images).
  • Peak Signal-to-Noise Ratio (PSNR): Logarithmic ratio between maximum possible signal power and noise distortion. $$\text{PSNR} = 10 \cdot \log_{10}\left(\frac{255^2}{\text{MSE}}\right) \text{ dB}$$ Typical LSB PSNR exceeds 50 dB ($\infty$ dB for identical images). Values $> 40\text{ dB}$ are visually imperceptible.

⚠️ 6. Lossless PNG Requirement & LSB Limitations

Why PNG / BMP and not JPEG?
JPEG uses lossy Discrete Cosine Transform (DCT) compression. When saving to JPEG, high-frequency spatial details (including modified LSBs) are discarded, destroying the embedded payload. PNG uses lossless DEFLATE compression, preserving pixel bit values exactly.

Real-World Steganography Limitations:

  • Non-Robust: LSB embedding does not survive image resizing, cropping, color adjustment, or lossy recompression.
  • Steganalysis Susceptibility: Statistical techniques (such as Chi-square ($\chi^2$) analysis and Sample Pairs analysis) can detect LSB flipping in unencrypted or low-entropy scenarios. Encrypting the payload before embedding provides pseudo-random high entropy, increasing detection difficulty.
